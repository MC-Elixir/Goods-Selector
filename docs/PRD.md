## 1. 背景与目标

### 1.1 业务背景

Amazon 跨境电商铺货 / 跟卖业务中，选品是利润和成功率的决定性环节。传统人工选品的痛点：

- Best Seller 榜单数据量大、刷新快，人工跟踪成本高
- 1688 找货源依赖经验，图文匹配效率低
- 利润测算分散在 Excel 中，参数变动难追溯
- 缺乏统一评分标准，主观决策成分高
- 卖家精灵数据需手动查询，无法批量化

### 1.2 目标

构建一套自动化选品流水线，输入"类目 + 抓取数量"，自动输出按综合评分排序的候选选品池及市场分析报告。

### 1.3 选品核心方法论

**四维优先级**（需求 > 利润 > 竞争 > 可行性）：

1. **市场需求**：是否有人买？规模多大？趋势如何？
  - 机会指数 > 0.05，Top100 日均销售额 > $50，月搜索量 ≥ 2000
2. **竞争环境**：竞争激烈吗？大卖主占比高吗？是否有蓝海机会？
  - 前四名销量占首页 < 40%，无国际品牌垄断，BSR 前 20 有低评论新品机会
3. **利润与成本**：净利率 ≥ 30%（最低容忍 20%），广告 ACOS < 25%
4. **运营可行性**：SKU 数量、供应链稳定、首单资金 < 5 万 CNY

**产品标准（硬性门槛）**：

- 月销量 ≥ 200 件（单 SKU），评论数 < 200（新品竞争可控）
- 平均售价 $15–$50，不带电、不带液体、非强季节性
- MOQ ≤ 500，供货周期 < 25 天，初始资金 ≤ 5 万 CNY

### 1.3 非目标

本期不做：可视化前端 / 多人协同 / 自动下单 / 库存管理 / 站外引流分析。

## 2. 用户与场景

### 2.1 用户角色


| 角色  | 职责          | 系统使用方式                 |
| --- | ----------- | ---------------------- |
| 选品员 | 调度流水线、评估候选品 | 命令行触发 + 阅读报告           |
| 运营  | 决定是否上架      | 阅读 Excel / Markdown 报告 |
| 开发者 | 维护评分规则、利润参数 | 编辑 YAML 配置             |


### 2.2 典型场景

**场景 A：每周类目扫描**

每周一上午跑 `python main.py run --category "Home & Kitchen" --limit 200`，3 小时内拿到该类目 Top 200 产品的评分表和 Top 20 详细市场分析。

**场景 B：手动验证单品**

针对某个 ASIN，手动跑利润测算和市场分析，验证人工初筛的产品是否值得跟进。

**场景 C：参数迭代**

发现某类产品评分偏高但实际亏损，调整 `profit_params.yaml` 中的 ACOS 默认值或 `scoring_weights.yaml` 中的权重，重新跑历史数据回归验证。

## 3. 功能需求

### 3.1 核心流程

```
Amazon BSR 抓取
      ↓
1688 拍立淘 图文匹配
      ↓
  [并行]
  ├─ 利润预测
  └─ 卖家精灵市场分析
      ↓
   多维度评分
      ↓
  硬性筛选 + 排序
      ↓
   报告导出
```

### 3.2 模块清单

#### M1 — Amazon Best Seller 数据采集

**输入**：类目、子类目（可选）、地区站点（US / UK / DE / JP）、数量。

**输出字段**：ASIN、标题、品牌、售价、BSR 排名、评分、评论数、30 天评论增速、主图、Listing URL、上架时间、物理尺寸（重量、长宽高）。

**实现**：优先调 Keepa API（约 19 USD/月起），备用 Rainforest API。不做自建爬虫。

**频率**：手动触发或 cron 定时。

---

#### M2 — 1688 拍立淘图文匹配

**输入**：Amazon 主图 URL（或本地图片字节）、商品标题（兜底关键词）。

**实现路径**：

1. 主路径：调 1688 拍立淘官方 API（图搜接口），按图片相似度返回 Top N 货源。
2. 兜底（本期不做）：本地 CLIP 向量召回 + 标题翻译关键词搜索。

**输出字段**：1688 offer ID、供应商名、URL、产品图、相似度（0-1）、MOQ、阶梯价、月销量、回头率、是否实力商家。

**阈值**：相似度低于 0.7 的过滤，单产品最多保留 Top 20 货源。

---

#### M3 — 利润预测模型

**公式**（来自真实目标采购成本表）：

$$\text{净利润} = \text{售价} - (\text{采购} + \text{头程} + \text{FBA} + \text{佣金} + \text{广告} + \text{退货} + \text{汇率损耗})$$

$$\text{净利率} = \text{净利润} / \text{售价} \quad \text{目标} \geq 30，容忍最低 20$$

**参数全部可配置**（`config/profit_params.yaml`）：


| 参数      | 来源                 | 默认值                         |
| ------- | ------------------ | --------------------------- |
| 采购价     | 1688 阶梯价中位         | 取 `default_batch_qty=200` 档 |
| 头程运费    | 配置表 × max(实重, 体积重) | 海运 LCL 2.8 USD/kg           |
| FBA 费   | 尺寸分档查表             | 标准件 3.43–5.95 USD           |
| 佣金率     | 类目映射               | 默认 15%                      |
| 广告 ACOS | 配置 / 卖家精灵          | 默认 **25%**（目标 <25%，新品期 35%） |
| 退货率     | 类目映射               | 默认 **6%**（服装 20%，电子 12%）    |
| 汇率损耗    | 配置                 | 1%；汇率 **6.88** CNY/USD      |


**体积重计算**：`L × W × H(cm) / 6000 = 体积重(kg)`，与实重取大值后计费。

**输出**：`ProfitSnapshot` —— 含每项成本明细 + 净利润 + 净利率 + 当时使用的参数版本快照。

---

#### M4 — 产品评分体系

**优先级原则**（来自真实选品方法论）：需求 > 利润 > 竞争 > 可行性

**6 个维度，加权得分制**（`config/scoring_weights.yaml`）：


| 维度    | 权重      | 评分逻辑                                           |
| ----- | ------- | ---------------------------------------------- |
| 市场需求  | **25%** | 机会指数 + Top100日均销售额 + 搜索量 + BSR + Google Trends |
| 利润率   | 20%     | sigmoid 曲线，30% 净利率约 0.5 分，50% 封顶               |
| 竞争烈度  | 20%     | 品牌垄断 + 前四销量集中度 + 头部收入占比                        |
| 货源稳定性 | 15%     | 供应商数 + 交期 + 初始资金 + FBA 经验                      |
| 物流友好度 | 10%     | 体积重比 ≤ 1.2、重量 ≤ 2kg、无危险属性                      |
| 风险等级  | 10%     | 大牌侵权、强制认证、季节性                                  |


**总分 = Σ(维度得分 × 权重) × 100**，范围 0–100。


| 总分    | 建议       |
| ----- | -------- |
| < 50  | 不做（硬性淘汰） |
| 50–64 | 可选，需人工复核 |
| ≥ 65  | 推荐，进入候选池 |


**硬性筛选**（不达标直接淘汰，仍入库便于回溯）：

- 净利率 < **20%**（目标 30%，最低容忍 20%）
- 总分 < 50
- 月销量 < 200 件
- 平均售价 < $15（且利润率未达 30%）
- MOQ > 500
- 供应商数 < 1
- 命中知名品牌词

---

#### M5 — 卖家精灵市场分析

**输入**：ASIN

**调用**：卖家精灵官方 API。

**输出字段**：主关键词、月搜索量、关键词难度、在售竞品数、Top 10 收入集中度、Top 10 平均评论数 / 价格、机会度评分、季节性波动。

**用途**：评分中的"市场需求"和"竞争烈度"维度依赖此数据；同时输出到候选品的市场分析报告中。

---

#### M6 — 报告导出

**三种产物**：

1. **Excel 候选选品表** —— 一行一个产品，含全部评分维度、利润明细、Top 1 货源链接。
2. **Markdown 详情报告** —— Top N 产品，每个一份独立 .md，含主图、评分原因、市场分析、推荐货源。
3. **JSON** —— 便于下游程序消费。

## 4. 数据模型

详见 `docs/database_schema.md`。核心 6 张表：

```
products              Amazon 产品主表
suppliers             1688 货源（一对多）
profit_snapshots      利润快照（每次跑都新增，不覆盖）
scores                评分历史
market_analyses       卖家精灵数据
run_logs              流水线执行日志
```

设计原则：

- 利润和评分均使用快照表，不在原表上覆盖更新，便于参数调整后回归对比。
- `params_snapshot` / `weights_snapshot` 字段保存当时参数 JSON，便于复现历史决策。

## 5. 非功能需求

### 5.1 性能

- 单类目 200 产品的全流程预期 ≤ 2 小时（瓶颈在外部 API 限流）。
- 数据库选型 SQLite（单机）即可满足，每月数据量预估 < 1 GB。后续如需多人共享再迁 PostgreSQL。

### 5.2 成本控制

外部 API 调用是主要成本来源，需要做到：

- 所有外部 API 调用经过 `diskcache` 文件级缓存，TTL 24h。
- 同一 ASIN 同一天内不重复调用卖家精灵。
- 1688 拍立淘按图片 hash 做去重缓存。

### 5.3 可观测性

- 所有外部调用、关键决策点用 `loguru` 记录。
- `run_logs` 表记录每次流水线的各阶段计数和 API 调用次数（用于成本审计）。

### 5.4 可维护性

- 评分权重、利润参数全部 YAML 化，调参不动代码。
- 每个评分函数 `score_*` 都是纯函数，单测覆盖。

### 5.5 合规

- 所有数据采集走 1688 和卖家精灵的官方 API，避免反爬合规风险。
- Amazon 数据建议走 Keepa / Rainforest 等合规第三方。

## 6. 配置约定

### 6.1 文件位置

```
config/
├── settings.py              代码层配置（从 .env 读 API key）
├── profit_params.yaml       利润模型参数（可热加载）
└── scoring_weights.yaml     评分权重和曲线（可热加载）
.env                          环境变量（不入库）
.env.example                  模板
```

### 6.2 配置变更流程

1. 改 YAML / .env
2. 跑 `pytest tests/` 确保单测通过（含权重和 = 1.0 的校验）
3. 取一批历史 RunLog 做回归对比
4. 提交 git，记录变更原因

## 8. 风险与开放问题

### 8.1 风险


| 风险                | 影响     | 缓解                         |
| ----------------- | ------ | -------------------------- |
| 1688 拍立淘 API 申请门槛 | 阻塞 M2  | 提前申请 + 兜底 CLIP 方案          |
| Amazon 数据源价格      | 持续成本   | 评估 Keepa Token 包用量，必要时换轻量源 |
| 评分模型过拟合           | 推荐质量差  | 用历史已上架产品做反向校准              |
| FBA 费用规则变化        | 利润预测失真 | 每季度更新 `profit_params.yaml` |


### 8.2 开放问题

1. Amazon 站点是否要支持多区？本期默认 US，UK/DE/JP 只做字段兼容不实测。
2. 候选品入库后是否做"已选品库"标记，避免重复推荐？建议下一版加。
3. 评分权重是否需要按类目差异化？目前全局一套，待 50 个真实产品数据后再决定。

## 9. 附录

### 9.1 术语


| 术语   | 解释                                                      |
| ---- | ------------------------------------------------------- |
| ASIN | Amazon Standard Identification Number，产品在 Amazon 的唯一 ID |
| BSR  | Best Seller Rank，类目内的销量排名                               |
| FBA  | Fulfillment by Amazon，亚马逊代发货物流服务                        |
| ACOS | Advertising Cost of Sales，广告销售比                         |
| MOQ  | Minimum Order Quantity，1688 起订量                         |
| 拍立淘  | 阿里巴巴的以图搜图能力，1688/淘宝共用                                   |
| 卖家精灵 | Sellersprite，跨境电商市场分析 SaaS                              |
